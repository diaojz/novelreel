# PRD · NovelReel：小说 → 推文短视频（教学版）

> 版本：v0.1 · 日期：2026-06-05
> 状态：MVP 阶段（文本闭环）

---

## 1. 一句话定位

NovelReel 是一个「小说 → 分镜剧本 → 推文短视频」的 AI 内容生产工具，同时也是一个**面向零基础学员的 AI 编排教学项目**——学员边学边造一个真实产品，每节课都能看到跑起来的效果。

---

## 2. 目标用户与场景

### 两类用户，视角不同

**用户 A：内容创作者（产品终端用户）**

- 是谁：写网文的作者、书号运营、短视频剪辑团队
- 场景：手里有一段小说（几百到几千字），想快速生成可用的短视频分镜剧本，目前靠手工拆场景、写台词，费时费力
- 当前如何解决：人工整理 + 剪映手动剪辑，或者用字节的「小云雀」平台（重但全）
- 想要什么：粘贴进去，三分钟出一份能用的分镜 JSON，不用自己动脑拆

**用户 B：零基础 AI 开发课学员（教学用户）**

- 是谁：没有编程背景、想学 AI 开发的普通人，正在上讲师的课
- 场景：课堂上跟着讲师一起，从零构建这个产品，每节课完成一个小功能
- 当前如何解决：跟着讲师操作，但如果只看视频不上手，很难真正理解
- 想要什么：每次课结束能自己跑起来一个新功能、能看到效果，代码是能逐行读懂的 Python

### 核心使用场景（典型路径）

一个创作者打开 NovelReel，把一段《斗破苍穹》的章节文本贴进去，点「开始处理」，系统自动：
1. 找出里面所有角色（萧炎、美杜莎……）和他们的外貌/性格描述
2. 找出场景（城墙外的荒漠）和道具（斗气护盾）
3. 把这段故事拆成 5 个分镜，每个分镜有画面描述、对白、情绪节奏
4. 输出一份 JSON，可以直接喂给后续生图/生视频模型

全程不需要用户写代码，也不需要手动拆场景。

## 3. 核心价值主张

**对内容创作者**：把「读小说 → 想分镜」这个最耗脑力的环节交给 AI，人只做最后的审核和微调。比手工快 10 倍以上。

**对零基础学员**：这是一个「麻雀虽小五脏俱全」的真实 AI 工程项目——它包含了 LLM 调用、多 Agent 编排、数据状态管理、API 设计、前端展示，学完等于把实际 AI 应用开发的核心骨架走了一遍。而且**所有编排逻辑都是明文 Python**，不藏在框架的黑盒里。

## 5. 核心流程（端到端）

### 5.1 整体工作流（MVP 阶段）

```
用户粘贴小说文本
       ↓
[阶段 0] 创建项目
  · 前端发 POST /projects
  · 保存原文到 samples/xxx.txt
  · 创建 project.json（状态：initialized）
       ↓
[阶段 1] 提取资产
  · 编排器检测到 characters/scenes/props 未填充
  · 调用 ExtractAssetsAgent
    → 传入：小说文件路径（不传原文本体）
    → 调用豆包 LLM，结构化输出角色/场景/道具
    → 结果写回 project.json（状态：assets_extracted）
       ↓
[阶段 2] 用户审核（可选跳过）
  · 前端展示提取结果
  · 用户可修改 / 确认
  · 确认后标记 assets_confirmed = true
       ↓
[阶段 3] 生成分镜剧本
  · 编排器检测到 script 未生成
  · 调用 GenerateScriptAgent
    → 传入：project.json 中的资产摘要 + 小说文件路径
    → 调用豆包 LLM，输出 scenes[] 数组 JSON
    → 写入 scripts/<project_id>.json（状态：script_generated）
       ↓
[阶段 4] 展示结果
  · 前端轮询状态接口，检测到 script_generated
  · 展示分镜剧本 + 提供下载/复制
```

### 5.2 编排器状态机（核心逻辑）

编排器是一个明文 Python 的状态机，判断逻辑极简：

```
while project.status != "done":
    if not project.assets_extracted:
        run ExtractAssetsAgent
    elif not project.assets_confirmed:
        wait for user confirmation  # 前端轮询时返回"等待确认"
    elif not project.script_generated:
        run GenerateScriptAgent
    else:
        project.status = "done"
```

每次 Subagent 完成后，编排器更新 project.json，然后继续循环——这就是「数据状态驱动工作流」的全部。

### 5.3 断点续传

因为状态全存在 project.json，任何一步崩溃后重新跑：
- `assets_extracted = true` → 跳过提取，直接进审核
- `script_generated = true` → 跳过生成，直接展示

## 6. 数据模型概述

### 6.1 project.json（每个项目一个，核心状态文件）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 项目 UUID |
| `title` | string | 项目名称（用户填写或自动从小说标题提取） |
| `novel_path` | string | 小说原文的文件路径 |
| `status` | enum | 当前整体状态：`initialized / extracting / assets_extracted / confirming / generating / script_generated / done / error` |
| `assets_confirmed` | bool | 用户是否已确认资产 |
| `characters` | list | 角色列表（见下） |
| `scenes` | list | 场景列表（见下） |
| `props` | list | 道具列表（见下） |
| `script_path` | string | 分镜剧本 JSON 的文件路径 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 最后更新时间 |

### 6.2 Character（角色）

| 字段 | 说明 |
|------|------|
| `name` | 角色名字（如"萧炎"） |
| `aliases` | 别名列表（如["小炎"，"萧少"]） |
| `appearance` | 外貌描述（一段自然语言，给生图用） |
| `personality` | 性格描述 |
| `role` | 在这段故事里的角色（主角/配角/反派/龙套） |

### 6.3 Scene（场景）

| 字段 | 说明 |
|------|------|
| `name` | 场景名（如"云岚宗门口"） |
| `description` | 环境描述（时段、天气、环境细节） |
| `mood` | 情绪氛围（紧张/轻松/悲伤……） |

### 6.4 Prop（道具）

| 字段 | 说明 |
|------|------|
| `name` | 道具名（如"玄重尺"） |
| `description` | 外观描述 |
| `significance` | 在剧情中的作用 |

### 6.5 Script（分镜剧本）

顶层是 `{ "project_id": "...", "scenes": [...] }`，每个 scene 包含：

| 字段 | 说明 |
|------|------|
| `index` | 分镜序号（从 1 起） |
| `shot_type` | 镜头类型（近景/中景/全景/特写） |
| `visual_description` | 画面描述（给文生图的 prompt 基底） |
| `characters_present` | 出镜角色名列表（只引用名字，不重复定义） |
| `dialogue` | 对白（可为空） |
| `caption` | 字幕文字 |
| `mood` | 情绪节奏 |
| `duration_hint` | 建议时长（秒，给视频生成用，MVP 阶段仅参考） |

## 7. 非功能需求

### 7.1 教学可讲解性（最重要）

- 编排逻辑必须是**明文 Python 状态机**，不能封装成「黑盒」——每一行代码在课堂上都要能讲清楚
- 禁止使用 Agent 框架（LangGraph、Claude Agent SDK、CrewAI 等）——框架内部的调度对学员是黑盒
- 每个 Subagent 是一个独立的 Python 函数/类，输入输出清晰，可以单独测试
- Pydantic 模型要有清晰的注释，字段语义一眼看懂

### 7.2 断点续传

- 任意阶段崩溃或手动中断后，重新触发编排器，它会从最后一个完成的步骤继续，不重复调用 LLM
- 状态完全由 project.json 决定，不依赖内存

### 7.3 模型可替换

- LLM 客户端封装成独立模块，切换模型只改配置（`MODEL_ID`、`BASE_URL`）
- 提示词（Prompt）与业务逻辑分离，单独存放，方便调试和对比
- 默认使用火山引擎豆包（`doubao-pro-32k`），配置后可换任何 OpenAI 兼容接口

### 7.4 本地可用

- 文本处理阶段（提取资产 + 生成剧本）只依赖 LLM API，无需本地 GPU，笔记本联网即可跑
- 无数据库依赖，所有数据落盘为本地 JSON 文件，课堂里直接 `ls` 就能看到产物

### 7.5 接口简洁

- FastAPI 接口保持最少原则：创建项目 / 触发编排 / 查询状态 / 获取结果，4 个核心接口就够
- 前端极简：一个 HTML 文件，不上 React/Vue 等框架，学员不需要懂前端

## 8. 不做什么（范围边界）

| 不做 | 原因 |
|------|------|
| 生成分镜图（P0 阶段） | MVP 先把文本编排骨架跑通，生图是 P1 |
| 生成视频 / 合成成片 | P2 阶段，需要接视频模型，成本和复杂度都高 |
| 用户账号 / 登录鉴权 | 教学项目，本地单机使用，不需要多用户 |
| 云端部署 / 多人协作 | 课堂环境是本地开发，不是 SaaS |
| 多语言支持 | 专门面向中文小说，不考虑英文 |
| 向量数据库 / RAG 长文处理 | MVP 阶段假设输入在 4000 字以内，塞进单次上下文 |
| 版权检测 / 内容过滤 | 教学场景，用户自己的素材，暂不做平台合规功能 |
| Agent 框架（LangGraph / CrewAI 等） | 对学员是黑盒，违背教学可讲解性原则 |
| 移动端 / App | Web 页面够用，不做 App |

## 9. 验收标准（MVP 怎么算做完）

### 功能验收

- [ ] 可以把一段 500–2000 字的中文小说文本粘贴进去，创建项目成功
- [ ] 系统能自动提取出不少于 2 个角色，每个角色有名字和描述
- [ ] 系统能自动提取出不少于 1 个场景
- [ ] 提取结果在前端可见，可以手动编辑
- [ ] 确认资产后，系统能自动生成不少于 3 个分镜，每个分镜有画面描述和对白
- [ ] 生成的分镜 JSON 可以在前端查看，并能复制或下载
- [ ] 中断后重新运行，系统从断点续传，不重复调 LLM

### 教学验收

- [ ] 编排器核心逻辑不超过 60 行明文 Python
- [ ] 每个 Subagent 是独立文件，可以单独 `python -m` 运行测试
- [ ] `uv run pytest` 能跑通基础单元测试（不调真实 LLM，用 mock）
- [ ] 一个零基础学员对照代码，能用自己的语言解释「编排器是怎么工作的」

### 性能基线（教学场景可接受）

- 提取资产阶段（500 字输入）：30 秒内完成
- 生成分镜（5 个镜头）：60 秒内完成
- 上述延迟是 LLM API 网络延迟决定的，不是代码瓶颈

## 10. 教学拆解建议

> 这一节是 NovelReel 作为教学项目的特有章节，每节课都要有「这节课能跑出来的效果」。

### 总体思路

课程沿着「从最薄的骨架，每节课加一层肉」的路线推进——每节课结束时，学员能在自己电脑上跑出一个新功能并看到输出。

### 推荐课程拆解（共 7 节，每节约 90 分钟）

---

**第 1 节：把 LLM 叫起来**

- 核心目标：能用代码调通豆包 API，拿到第一个 LLM 回复
- 学员产出：一个 `hello_llm.py`，输入"你好"，打印模型回复
- 知识点：环境搭建（uv）、.env 配置、OpenAI SDK 用法、token 计费概念
- 里程碑感：「原来调 AI 就这几行代码」

---

**第 2 节：数据模型 + 项目骨架**

- 核心目标：定义 Character / Scene / Prop / Project 的 Pydantic 模型，能创建并保存 project.json
- 学员产出：跑一个脚本，创建项目，打开目录能看到 `project.json` 文件
- 知识点：Pydantic 数据模型、JSON 序列化、文件 I/O、UUID
- 里程碑感：「我的数据结构设计好了」

---

**第 3 节：第一个 Subagent——提取资产**

- 核心目标：写 `ExtractAssetsAgent`，能从一段小说里提取角色/场景/道具，写回 project.json
- 学员产出：运行 `python -m novelreel.agents.extract_assets <novel_path>`，看到 project.json 被更新
- 知识点：结构化输出（LLM 返回 JSON）、Prompt 工程基础、异常处理
- 里程碑感：「AI 真的能从小说里认出人物」

---

**第 4 节：第二个 Subagent——生成分镜剧本**

- 核心目标：写 `GenerateScriptAgent`，能根据资产 + 小说生成 scenes[] JSON
- 学员产出：运行脚本，在 `scripts/` 目录下看到一份分镜 JSON 文件
- 知识点：多轮 Prompt 设计、JSON Schema 约束、数据引用（角色只写名字）
- 里程碑感：「AI 帮我写了分镜，格式还挺对」

---

**第 5 节：编排器——把两个 Agent 串起来**

- 核心目标：写明文 Python 编排器，自动按顺序调用两个 Subagent，处理异常和状态
- 学员产出：运行 `python -m novelreel.core.orchestrator <project_id>`，全程自动完成
- 知识点：状态机思维、数据驱动工作流、断点续传设计
- 里程碑感：「我理解了 Agent 编排是什么意思」

---

**第 6 节：FastAPI 接口 + 极简前端**

- 核心目标：把编排器包装成 HTTP API，写一个 HTML 页面贴文本、看结果
- 学员产出：浏览器里能完成完整流程（贴文本 → 等待 → 看分镜）
- 知识点：FastAPI 路由、异步任务（Background Tasks）、轮询状态、纯 HTML/JS fetch
- 里程碑感：「有点像真正的产品了」

---

**第 7 节：复盘 + 扩展方向**

- 核心目标：回顾整个架构，讨论「如果要加生图该怎么接」，展望 P1
- 学员产出：一份架构图（手绘或用 AI 画），标注每一层的职责
- 知识点：P1 生图方案预研（文生图模型接入方式）、整体回顾、独立完成小作业
- 里程碑感：「我能解释这个产品的技术架构」

---

### 每节课的设计原则

1. **先看效果，再讲原理**：每节课在前 15 分钟先 demo 这节课要做出来的东西，让学员知道终点在哪
2. **代码量可控**：每节课新增代码量控制在 80–150 行，不能太多
3. **可失败、可调试**：刻意设计一个会出错的场景（如 API Key 没配），让学员学会看错误信息
4. **有回家作业**：每节课给一个微改动（比如改提示词、加一个新道具字段），学员自己做完发截图

## 11. 已决策事项（2026-06-05 产品负责人拍板）

| # | 问题 | **决策** | 影响范围 |
|---|------|---------|---------|
